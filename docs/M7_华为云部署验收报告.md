## 4. 为部署所做的代码改动

| 文件 | 改动 | 原因 |
|---|---|---|
| `src/device.py` | 由空文档字符串实现为设备层：`register_npu()` / `pick_device()` / `device_report()` | `torch` 不会自动加载 `torch_npu`，`npu:0` 无法使用 |
| `src/ffmpeg_util.py` | 新增：按 `SG_FFMPEG` → PATH（须含 libmp3lame）→ `imageio-ffmpeg` → 旧路径 定位 ffmpeg | 云端系统 ffmpeg 4.2 无 MP3 编码器 |
| `src/pipeline.py` | 接 `pick_device`；CLI 加 `--device`；`_ffmpeg()` 改走 `ffmpeg_util` | 设备选择 + MP3 编码 |
| `src/content/mp3_crypto.py` | `encode_mp3` 默认使用 `find_ffmpeg()` | 同上 |
| `tests/test_mp3_crypto.py` | 测试用 ffmpeg 改为 `find_ffmpeg()` | 同上 |
| `app/main.py` | 启动打印设备报告；新增 `--device/--host/--port/--share` | 支持 `0.0.0.0` 监听与 NPU 自动选择 |

改动均为**向后兼容**：本地 Windows/CUDA 环境走原路径，不影响既有 M1–M6 结果。

## 5. 问题与处理

| # | 现象 | 根因 | 处理 |
|---|---|---|---|
| 1 | `module 'torch' has no attribute 'npu'` | torch 不自动 import torch_npu | 新增 `src/device.py` 显式注册 |
| 2 | `Expected one of cpu, cuda, ... device type` | 同上 | 同上 |
| 3 | `Default encoder for format mp3 ... disabled` | 系统 ffmpeg 4.2 未编入 libmp3lame | `imageio-ffmpeg` + `src/ffmpeg_util.py` 兜底 |
| 4 | transformers 报 `huggingface-hub<1.0 is required` | gradio 5/6 升级了 hub | 锁 `gradio==4.44.1`、`hub==0.29.1` |
| 5 | 前端 500：`argument of type 'bool' is not iterable` | pydantic 2.11 与 gradio 4.44 不兼容 | `pydantic==2.9.2` |
| 6 | `ImportError: cannot import name 'DEFAULT_CIPHERS'` | urllib3 2.x 与旧 botocore 冲突 | `urllib3<2` |
| 7 | `test_pipeline` IndexError | 测试需要 ≥4 条 LibriSpeech flac | 上传 1 个 chapter |
| 8 | `scp: path canonicalization failed` | 目标父目录不存在 | 先 `mkdir -p` |
| 9 | 本机 `scp` 看不到刚生成的文件 | Bash 沙箱文件视图隔离 | 改用 `cat f \| ssh 'cat > f'` |
| 10 | 结束进程时把当前 SSH shell 一起杀掉 | `pkill -f` 匹配到自身命令行 | 用 pgrep 取 PID，或用 `[a]pp.main` |
| 11 | Gradio share 403 | 代理拦截 frp 7000 端口 | 改用 SSH 转发 / Pinggy |
| 12 | Pinggy 隧道数分钟断开 | 平台代理切断空闲长连接 | 加 `ServerAliveInterval=10` 与 `sleep infinity \|` |

## 6. 结论

1. **部署可行**：SpeechGuard-Replica 在华为云 910B4 + torch_npu 上无需修改算法逻辑即可运行，
   仅需补充设备注册与 ffmpeg 定位两类环境适配。
2. **主链路正确**：转写、敏感词检测、帧加密、MP3 三态发布、权限恢复均产出预期结果，
   与本地 M5/M6 验证结论一致。
3. **性能可接受**：3.1s 音频端到端（含首次模型加载）35.4s，其中发布阶段 0.15s；
   模型常驻后重复调用会明显下降。
4. **公网服务未达标**：临时隧道可演示但不满足"随时可访问"，正式验收需建设在线服务或固定映射。

## 8. 遗留与后续建议

1. **长期公网端点**：建议 ModelArts 在线服务（自定义镜像 → SWR → 在线服务），
   或 ECS + Docker Compose + 安全组固定端口；当前隧道仅适合临时演示。
2. **完整数据复现**：本次未上传 LibriSpeech/VCTK 全集，Table 5/6/7 未重跑；
   若需云端复现实验结果，需追加约 13GB 数据与相应算力时间。
3. **框架口径**：当前为 PyTorch + torch_npu。若课程要求 MindSpore，
   需将 BERT NER 等单点替换为 MindSpore Hub 等价实现，主链路不变。
4. **依赖固化**：建议把本次锁定版本写入 `deploy/requirements-cloud.txt`，
   避免后续重装再次触发版本冲突。
